💬 Commentaries:

Completes the IAM permissions-domain alignment (IAM v1.3.0): re-enables permission enforcement
using the new tag-based permissioning standard.

---

✨ Added:

    ▸ Seed `dbseeds/1795316490_settings-permissions.php`, registering the module's permission tags
      in `IAM_PERMISSION`: `settings.settings.read` / `.manage` and
      `settings.customfield.read` / `.manage`.

---

🔧 Changed:

    ▸ Replaced the entity/CRUD permission codes (`STT_SETTINGS`, `STT_SETTINGS_CUSTOMFIELD`) with
      tag-based permissions enforced via `iam/permission->requireAny()`. Writing a setting requires
      `settings.settings.manage`; creating or deleting a custom field requires
      `settings.customfield.manage`. Read endpoints remain open as before.

    ▸ Module presence is now checked via `ModsManager::modExists('iam')`, and the disabled
      `validatePermissions()` reference was removed.
